## The Correct Product Vision

### What ProjectPulse Actually IS

**A web-based project management platform** (like Jira, Linear, or GitHub) that stores all project data in a cloud database and provides:

1. **Web UI for Humans:**
   - Wiki page (searchable documentation)
   - Knowledge Base (RAG with semantic search)
   - Issues page (bug/feature tracking)
   - Tickets page (sprint work items)
   - Development Cycle page (hierarchical progress)
   - Dashboard (project overview)

2. **MCP API for AI Agents:**
   - 41 MCP tools for CRUD operations
   - Vector search for knowledge queries
   - Progress tracking tools
   - Issue/ticket management tools

3. **Database Storage:**
   - PostgreSQL as single source of truth
   - ALL data stored in database (NOT local files)
   - User's repository stays CLEAN (no .agent/ folder)

### End User Journey (Correct)

```
1. Developer visits projectpulse.com
   └─> Creates project "My E-commerce App"
   └─> Gets API key

2. Opens IDE, starts AI agent (Claude Code/Cursor)
   └─> Agent connects to ProjectPulse via MCP

3. Onboarding (Agent-driven, ProjectPulse-guided):
   Session 1: ProjectPulse sends prompt → Agent asks 10 questions → Stores executive summary in database
   Session 2: ProjectPulse sends prompt → Agent generates docs (PRD, SRS) → Stores in database
   Session 3: ProjectPulse sends prompt → Agent creates AI workflow → Stores in database

4. Daily Development:
   - Agent creates issues → via MCP → Visible in ProjectPulse Issues page
   - Agent stores docs → via MCP → Visible in ProjectPulse Wiki page
   - Agent queries knowledge → via MCP → RAG search returns results
   - User monitors → via browser → Dashboard shows all activity

5. Result:
   - User's repo stays CLEAN (no .agent/ folder, no markdown clutter)
   - All data searchable via web UI
   - All data accessible via MCP API
```

### What End Users DON'T Get

- ❌ .agent/ folder in their repository
- ❌ CLAUDE.md file in their repository
- ❌ Markdown files (STATUS.md, DEVELOPMENT_PLAN.md, etc.)
- ❌ Any local files generated by ProjectPulse

- **Impact:** High (agents can't connect)
- **Mitigation:** Use existing API key pattern from Mac mini communication protocol
- **Testing:** Test with multiple API keys, invalid keys, expired keys

**Risk 3: Full-Text Search Performance**
- **Probability:** Low
- **Impact:** Medium (slow search results)
- **Mitigation:** Create PostgreSQL GIN index on `to_tsvector(content)`
- **Monitoring:** Log slow queries (>200ms)
- **Fallback:** Simple LIKE query if full-text search degrades
