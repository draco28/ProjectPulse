## 🔍 Technical Decisions Log

### Decision 1: Prisma Nested Write vs Manual Loop

**Context**: Creating phase with N child weeks atomically

**Options Evaluated**:
1. Manual loop with `prisma.$transaction()` - Traditional approach
2. Prisma nested write - `phase.create({ data: { weeks: { create: [...] } } })`

**Decision**: Use Prisma nested write (Option 2)

**Rationale** (from Prisma Expert):
- 3x faster performance (50ms vs 150ms)
- Single query instead of N+1 queries
- Built-in atomicity (no manual transaction needed)
- Cleaner code (declarative vs imperative)

**Implementation**: `apps/web/app/api/phases/route.ts` lines 87-99

### Decision 2: Select vs Include for Nested Queries

**Context**: Fetching task with 3-level hierarchy (day → week → phase)

**Options Evaluated**:
1. `include` - Fetch all fields (simpler code)
2. `select` - Fetch specific fields only (more verbose)

**Decision**: Use `select` (Option 2)

**Rationale** (from Prisma Expert):
- 52% smaller payload (significant for nested queries)
- Faster database query (fewer columns retrieved)
- More explicit about data requirements
- Better for API performance (NFR-019: <500ms response)

**Implementation**: `apps/web/app/api/tasks/current/route.ts` lines 34-73

### Decision 3: API Routes vs Server Actions

**Context**: MCP tools need to call Next.js from external process

**Options Evaluated**:
1. Server Actions - Modern Next.js pattern for forms
2. API Routes - Traditional HTTP endpoints

**Decision**: Use API Routes (Option 2)

**Rationale** (from Next.js Expert):
- MCP server calls via HTTP (external process)
- Need standard REST responses (JSON + status codes)
- Server Actions are for internal form submissions
- API Routes provide discoverability and middleware support

**Implementation**: `apps/web/app/api/phases/route.ts`, `apps/web/app/api/tasks/current/route.ts`

### Decision 4: Performance Index on Task.updatedAt

**Context**: getCurrentTask query performance

**Decision**: Add `@@index([updatedAt(sort: Desc)])` to Task model

**Rationale** (from Prisma Expert):
- 100x faster queries on large datasets (2ms vs 200ms)
- Query uses `orderBy: { updatedAt: 'desc' }` - index makes this instant
- Critical for real-time task queries (frequently called by MCP tools)

**Implementation**: `apps/web/prisma/schema.prisma` line 156

**Migration Required**: `npx prisma migrate dev --name add_task_updated_at_index`

### Code Patterns to Follow

**MCP Tool Structure**:
```typescript
import { z } from 'zod';
import type { ToolDefinition, ToolContext } from './types.js';

const schema = z.object({ /* validation */ });
type Input = z.infer<typeof schema>;

interface ApiResponse<T> { success: boolean; data?: T; error?: {...} }
interface ResponseData { /* API response shape */ }

async function handler(input: Input, context: ToolContext): Promise<string> {
  const response = await context.httpClient.METHOD<ApiResponse<ResponseData>>(url, data);
  return JSON.stringify({ /* formatted response */ }, null, 2);
}

export const toolDefinition: ToolDefinition = {
  name: 'projectpulse.tool.name',
  description: '...',
  schema,
  inputSchema: { /* JSON Schema */ },
  execute: async (params, context) => {
    const result = await handler(params as Input, context);
    context.logger.info('Tool completed', { /* metadata */ });
    return { content: [{ type: 'text', text: result }] };
  },
};
```

**Next.js API Route Structure**:
```typescript
import { NextRequest, NextResponse } from 'next/server';
import { z } from 'zod';
import { prisma } from '@/lib/prisma';

export const dynamic = 'force-dynamic'; // For GET routes

const schema = z.object({ /* validation */ });

export async function METHOD(request: NextRequest) {
  try {
    const validated = schema.parse(await request.json());
    const result = await prisma.model.operation({ /* query */ });
    return NextResponse.json({ success: true, data: result }, { status: 201 });
  } catch (error) {
    if (error instanceof z.ZodError) {
      return NextResponse.json({ success: false, error: { code: 'VALIDATION_ERROR', message: error.errors[0].message } }, { status: 400 });
    }
    return NextResponse.json({ success: false, error: { code: 'INTERNAL_ERROR', message: 'Operation failed' } }, { status: 500 });
  }
}
```

## 💡 Lessons Learned

### What Went Well

1. **Expert Consultation**: Invoking Next.js and Prisma experts early (Protocol Step 3) provided critical optimizations:
   - Prisma nested write pattern (3x performance improvement)
   - Select vs include optimization (52% payload reduction)
   - Index requirement identified (100x query speedup)

2. **Declarative Tool Design**: Following MCP ToolDefinition pattern made registration clean and type-safe

3. **API Response Consistency**: Using `{ success, data, error }` format across all endpoints simplifies error handling

### What Could Be Improved

1. **TypeScript Type Safety**: Should have defined API response interfaces earlier - would have caught generic type issues during implementation

2. **Database Availability**: Running Prisma migration during session would have validated index creation

3. **Testing Strategy**: Unit tests deferred to Day 7 - could have written tests alongside implementation for faster feedback

### Recommendations for Day 8+

1. **Define Types First**: Create API response interfaces before implementing handlers
2. **Test as You Go**: Write unit tests immediately after implementing each tool
3. **Database-First**: Ensure database is running before starting Prisma-dependent work
4. **Incremental Build**: Run `npm run build` after each file to catch errors early
