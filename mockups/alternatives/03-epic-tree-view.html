Option 3: Epic Tree View (Work Breakdown Structure)

✓ Advantages

  • • Pure work hierarchy: Epic → Feature → Task
  • • NO time dimension (no sprints, no days, no weeks)
  • • Progress = tasks complete (very concrete)
  • • Agent can claim any task directly
  • • Natural "feature complete" checkpoints
  • • Easy dependency visualization (feature blocks feature)
  • • Matches how developers think about scope

✗ Disadvantages

  • • No timeline at all (can't answer "when will X ship?")
  • • Needs separate sprint/release planning view
  • • May grow very deep (Epic → Feature → Sub-feature → Task)
  • • Harder to balance workload over time
Key Change: Ticket.kind becomes the level indicator (epic/feature/task). Parent-child via parentTicketId. DELETE all roadmap models (Phase/Sprint/Week/Day). Optional: add targetSprintNumber on tickets for loose scheduling.
