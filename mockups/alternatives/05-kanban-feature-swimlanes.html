Enhancement A: Feature Swimlanes

What this solves

  • • Parent/child clutter: children stay inside their feature lane
  • • Faster scanning: you read work per feature, not per status
  • • Easy rollups: % complete is derived from `childTickets`

Tradeoffs

  • • Slightly heavier layout (grid inside each feature)
  • • Still needs a “focus mode” for cross-feature bugs
  • • If a feature has 50 children, it still needs collapse
Data mapping: Swimlane = Ticket(kind='feature'); cards inside lane = Ticket(parentTicketId=feature.id). Scheduling uses scheduledWeekId + scheduledDays + estimatedDays.
