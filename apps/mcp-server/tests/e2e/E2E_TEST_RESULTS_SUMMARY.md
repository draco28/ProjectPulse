## Test Infrastructure

### Raw SSE + JSON-RPC Client Implementation

**Implementation**: [apps/mcp-server/tests/e2e/setup/mcp-client.ts](./setup/mcp-client.ts)

**Why Raw Protocol?**
- ❌ `@modelcontextprotocol/sdk` Client SDK is broken (`resultSchema.parse is not a function`)
- ✅ Raw implementation matches how real agents (Claude Code, Cascade) connect
- ✅ Bidirectional communication via SSE events + HTTP POST

**Protocol Flow**:
1. `GET /mcp` → Establish SSE stream, receive sessionId
2. `POST /mcp?sessionId=X` → Send JSON-RPC requests (HTTP 202 Accepted)
3. Listen for `message` events on SSE stream → Receive JSON-RPC responses
4. Match response.id to request.id → Resolve promise

**Key Features**:
- Configurable timeout per request (default: 30s, max: 90s tested)
- Automatic JSON parsing with fallback for formatted text
- Pending request tracking with timeout cleanup
- Connection state management

## API Bugs Discovered

### Bug 1: Duplicate Question IDs Across Subsections

**Severity**: MEDIUM
**Impact**: Only 3 answers saved per phase instead of 9-12

**Details**:
```typescript
// API returns questions with duplicate IDs
phase1_q1, phase1_q2, phase1_q3 (for subsection 1)
phase1_q1, phase1_q2, phase1_q3 (for subsection 2) // DUPLICATE IDs!
phase1_q1, phase1_q2, phase1_q3 (for subsection 3) // DUPLICATE IDs!

// When saving answers, later answers overwrite earlier ones
{ phase1_q1: "answer 1" }  // saved
{ phase1_q1: "answer 4" }  // OVERWRITES answer 1
{ phase1_q1: "answer 7" }  // OVERWRITES answer 4

Result: Only 3 answers per phase instead of 9
```

**Fix Required**:
- Change question ID format to include subsection
- `phase1_q1` → `phase1_subsection1_q1`
- Or use numeric IDs that are globally unique

**Affected Endpoint**: `GET /api/onboarding/questions`
**File**: [apps/web/app/api/onboarding/questions/route.ts](../../web/app/api/onboarding/questions/route.ts)

## Conclusion

### What Works ✅

- **MCP Protocol**: Raw SSE + JSON-RPC bidirectional communication working perfectly
- **Session 1**: Complete 10-phase onboarding + executive summary generation
- **Small Responses**: All tools returning <15KB work flawlessly
- **Validation**: Prerequisite checks and field validation functioning correctly

### What's Blocked ❌

- **Large Responses**: MCP SSE layer silently fails for responses >30KB
- **Session 2**: Cannot fetch 15 document prompts (31KB response)
- **Session 3**: Likely blocked by same issue (large bootstrap response)
- **tools/list**: Catalog listing times out (likely 20-30KB)

### Critical Insight 💡

**The HTTP APIs are fast and reliable** - this is purely an MCP transport layer bug. The Next.js API returns 31KB in 0.19 seconds, but the MCP server cannot relay this through SSE.

### Recommendation 🎯

1. **Immediate**: Implement pagination for `getDocumentPrompts` (5 docs per page)
2. **Short-term**: Fix MCP SSE layer or add response size limits
3. **Long-term**: Proper streaming/chunking architecture for large payloads

**Overall Assessment**: 🟡 MCP infrastructure needs critical bug fix before production deployment.
