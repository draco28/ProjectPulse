# Incident Report: Low Quality Onboarding Document Generation

**Date:** 2025-11-23
**Severity:** Medium (User Rejection)
**Component:** Onboarding Session 2 (Document Generation)
**Reporter:** Assistant (Draco)

## 1. Summary
During the End-to-End (E2E) test of the Onboarding System, the initial batch of documents (Batch 1: Planning) generated by the Client Agent was rejected by the user. The documents were described as "too brief" and "poor quality," lacking the depth expected of a professional Project Plan. The agent had to manually delete and regenerate the documents with a higher fidelity prompt strategy.

## 2. Timeline
*   **12:30:** User initiates Session 2 Batch 1 generation.
*   **12:35:** Agent generates 4 documents (PRD, SRS, Backlog, Project Plan) using standard prompts.
*   **12:38:** User reviews content and rejects it. "Project Plan is just a list of dates. PRD is 300 words."
*   **12:40:** Agent acknowledges the issue.
*   **12:45:** Agent manually deletes existing documents via SQL (developer override).
*   **12:50:** Agent regenerates Batch 1 with "Senior Engineer" persona and strict word count targets (>1500 words).
*   **12:55:** User approves the new content.

## 3. Root Cause Analysis
*   **Prompt Engineering:** The default system prompts provided by `getDocBatchPrompt` were functional but lacked *quality constraints*. They asked for "a PRD" but didn't specify "detailed, industry-standard, 2000-word PRD with success metrics."
*   **Agent Optimization:** The AI agent, aiming for efficiency, generated the "minimum viable response" to satisfy the tool contract, rather than the "maximum value response" for the user.
*   **Lack of Feedback Loop:** There is no "Draft -> Review -> Refine" step in the current API. It's a one-shot "Store Batch" operation.

## 4. Resolution
*   **Immediate Fix:** The agent adopted a "Simulation Mode" where it explicitly simulated a "Senior PM/Architect" writing high-density content, ignoring the brevity of the default prompt.
*   **Verified Success:** Batches 2, 3, and 4 were generated with this high standard and accepted without revision.

## 5. Recommendations & Prevention
1.  **Enhance Prompt Templates:** Update the database seeds for `OnboardingDocumentTemplate` to include strict word counts (e.g., "Minimum 1500 words") and required sections.
2.  **Implement Review Step:** Add a "Draft" status to documents, allowing the user to review and request edits before finalizing (Session 2 currently auto-completes).
3.  **Update/Overwrite API:** Implement `PUT /api/onboarding/documents/:id` to allow agents to refine documents without SQL deletion hacks.
